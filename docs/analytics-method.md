# 分析手法

計算はすべて `src/analytics/` の純粋関数で行い、UIからは独立しています。

## 1. 期待値（`expectedValue.ts`）
オッズ＝的中時の総払戻倍率、確率 p は 0〜1 とします。

- **期待払戻倍率** = p × オッズ
- **期待収益率** = p × オッズ − 1
- **オッズ逆算確率** = 1 ÷ オッズ（控除率を含むため、全買い目の合計は1を超える）
- **損益分岐オッズ** = 1 ÷ p

### 入力検証
| 入力 | 扱い |
|---|---|
| p が null / undefined | エラー `missing` |
| p が NaN・±∞・数値以外 | エラー `not_a_number` |
| p < 0 または p > 1 | エラー `out_of_range`（±1e-9 以内の浮動小数点誤差は丸める） |
| オッズが null | エラー `missing`（未発売・欠場）。期待値は「算出不可」と表示 |
| オッズが NaN・±∞ | エラー `not_a_number` |
| オッズ < 1.0 | エラー `below_minimum`（払戻は最低100円＝1.0倍のため） |
| オッズ ≥ 10000 | 計算はするが `unusually_high` の警告を付ける |
| p × オッズ ≥ 2 | 計算はするが `model_market_divergence` の警告（⚠要検証）を付ける |

閾値で絞り込むときは 1e-9 の許容誤差を入れています。0.5×2.4−1 = 0.19999999999999996 のような誤差で、ちょうど20%の候補が落ちないようにするためです。

## 2. 推定確率（`probabilityModel.ts`）
### モデルのインターフェース
`PredictionModel.predictWin(race, ctx)` が各艇の1着確率（合計1、欠場艇は0）を返します。データが足りないときは確率を作らず、エラー `insufficient_data` を返します。返り値には「使った要素」と「欠損のため使わなかった要素」が含まれ、画面に表示されます。

### モデル1：コース別基準モデル
1. 過去レースから、場ごと・コースごとの1着率を数える（失格などで着順のない出走は除く）。
2. 全場平均をラプラス平滑化する：prior = (1着数+1) ÷ (出走数+6)
3. 場の値を全場平均に寄せる：rate = (場の1着数 + 30×prior) ÷ (場の出走数 + 30)
4. 進入コースは、展示で6艇の進入がすべて揃っていればそれを使い、揃っていなければ枠なりとみなす。
5. 欠場艇を0にして、合計が1になるよう正規化する。

過去レースが30件未満のときは推定しません。

### モデル2：複合デモモデル
コース別基準の確率に、対数オッズの補正 exp(Σ) をかけて正規化します。

| 要素 | 補正（デモ係数・**未検証**） |
|---|---|
| 級別 | A1 +0.35 / A2 +0.15 / B1 0 / B2 −0.30 |
| 全国勝率 | (勝率 − 5.0) × 0.15 |
| モーター2連率 | (2連率% − 35) × 0.01 |
| 展示タイム | (タイム − 出走艇の平均) × (−4)　※0.1秒速いと +0.4 |

欠損している要素はその艇の補正に使わず（0とはみなさない）、「未使用要素」として表示します。

### 連勝式への展開（Harville 法）
P(i→j→k) = pᵢ × pⱼ/(1−pᵢ) × pₖ/(1−pᵢ−pⱼ)

全買い目の合計は1になります（テストで検証済み）。Harville 法は「2着・3着の争いも1着確率に比例する」と仮定するため、実際には本命の2・3着率を過小評価し、人気薄を過大評価する傾向が知られています。

## 3. モデル検証（`evaluation.ts`）
確定したレースで各モデルを評価します。
- **多クラス Brier スコア**：Σ(pᵢ − 1[i=1着])²。一様予測で約0.83。小さいほど良い
- **対数損失**：−ln p(1着艇)。一様予測で ln6 ≈ 1.79
- **本命1着率**：最大確率の艇が1着になった割合

**サンプルデータでの評価結果は実際の精度を示しません。** サンプルは、複合デモモデルと似た構造（コース×級別×モーター）の乱数で作っているため、評価が甘く出ます。実データを投入して初めて意味のある検証になります。

### 将来の検証手順（推奨）
1. 実データの過去成績を `HistoricalRace` と `Race` に変換して投入する。
2. 期間で学習用と検証用に分ける（未来のデータを使わないように、時系列で分割する）。
3. 係数を学習用期間で推定する（例：条件付きロジットや多項ロジスティック回帰）。
4. 検証用期間で Brier と対数損失を比べ、さらにオッズを使ったバックテストで回収率を確認する。
5. 十分な件数（目安：数千レース以上）で改善を確認できたら `validated: true` にする。

## 4. 展示情報の集計（`exhibition.ts`）
- 対象指標（すべて小さいほど良い）：展示タイム、直線、回り足、周回展示、展示ST
- 順位は同値が同順位（1,2,2,4…）。欠損と欠場は順位・平均・最良の計算から除外する。
- 艇ごとの平均順位は、値のある指標だけで計算する。全指標が欠損なら null。
- 画面では欠損を「データなし」と表示する。

## 5. 場別・コース別統計（`venueStats.ts`）
- 1着率・2連対率・3連対率の分母は、着順が確定した出走数。
- 条件：場、風速（0〜2 / 3〜4 / 5m以上）、波高（0〜2 / 3〜5 / 6cm以上）、期間。条件を指定したとき、風速や波高が欠損しているレースは対象外にする（0とはみなさない）。
- 対象件数と期間を必ず表示し、100件未満なら「偏りが大きい」と警告する。件数0のときの率は null（0%とは区別する）。

## 6. 振り返り（`history.ts`）
- 照合：確定レースの着順と買い目を比べる。払戻 = 結果の払戻(円/100円) × 購入額 ÷ 100。
- 的中率 = 的中数 ÷ 確定数、回収率 = 払戻合計 ÷ 購入合計。
- 的中したが払戻データがない記録は集計から除外する。結果待ちも除外する。
- **サンプル（source=sample）と実績（source=actual）は混ぜずに別々に集計する。**

## 7. 注目レース（`insights.ts`）
- 推定本命の1着率が40%未満（混戦）
- 1号艇以外が推定本命
- 展示タイムの最速と最遅の差が0.2秒以上

## 8. 表示上の方針
- 推定確率は「未検証のデモモデル」によるものと明示し、利益を保証する表現は使わない。
- 期待収益率の正負は色に加えて ▲▼ でも示す。
- 推定確率がオッズ逆算確率の2倍以上の候補には「⚠要検証」を付ける。乖離が大きいほど、利益機会よりモデル誤差である可能性が高いためです。
