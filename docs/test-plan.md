# テスト計画と実施結果

## 1. 方針
- 計算ロジック（`src/analytics/`）は純粋関数の単体テストで網羅する。境界値・異常値・欠損を重点的に扱う。
- 画面は Testing Library で利用者の操作（選択・入力・クリック・画面遷移）を再現する結合テストを行う。
- ビルド（型チェック込み）が通ることを確認する。
- スマートフォン表示は、実ブラウザ（Chromium）で 390×844 のビューポートを使い、自動で確認する。

## 2. 実行方法
```bash
npm test            # 単体＋UIテスト（Vitest）
npm run typecheck   # 型チェック
npm run build       # 型チェック＋本番ビルド
npm run check       # 上記をまとめて実行
```

## 4. 実施結果（2026-10-22、Node.js 22.22.0）

| 項目 | 結果 |
|---|---|
| `npm test` | **10ファイル・100テストすべて成功** |
| `npm run typecheck` | 成功（エラー0） |
| `npm run build` | 成功 |
| PC表示（1366×900, Chromium） | 9画面をスクリーンショットで目視確認。横方向のはみ出し0px、コンソールエラー0件 |
| スマートフォン表示（390×844, isMobile/hasTouch, Chromium） | 9画面で横方向のはみ出し0px、コンソールエラー0件。下部ナビが固定表示（7項目）され、出走表がカード表示に切り替わることを確認。オッズ表は表の枠内で横スクロールする（scrollWidth 522 > clientWidth 356、overflow-x:auto）。下部ナビのタップでの画面遷移と、券種チェックボックスのタップで件数が変わる（120→126件）ことを確認 |

テスト中に見つけて修正した不具合：
1. 期待収益率がちょうど閾値（例：20%）の候補が、浮動小数点誤差（0.19999999999999996）で除外されていた → 比較に許容誤差を追加
2. 過去に1着0回のコースの確率が厳密に0になっていた → 全場平均にラプラス平滑化を追加
3. サンプルデータで「風向：無風／風速4m」のような矛盾した値が出ていた → 生成スクリプトを修正
4. 期待収益率が+600%などの極端な候補がそのまま上位に出ていた → 「⚠要検証」の警告を追加
