# テスト計画と実施結果

## 1. 方針
- 計算ロジック（`src/analytics/`）は純粋関数の単体テストで網羅する。境界値・異常値・欠損を重点的に扱う。
- 画面は Testing Library で利用者の操作（選択・入力・クリック・画面遷移）を再現する結合テストを行う。
- ビルド（型チェック込み）が通ることを確認する。
- スマートフォン表示は、実ブラウザ（Chromium）で 390×844 のビューポートを使い、自動で確認する。

## 2. 実行方法
```bash
npm test            # 単体＋UIテスト（Vitest）
npm run typecheck   # 型チェック
npm run build       # 型チェック＋本番ビルド
npm run check       # 上記をまとめて実行
```

## 4. 実施結果（2026-10-22、Node.js 22.22.0）

| 項目 | 結果 |
|---|---|
| `npm test` | **12ファイル・130テストすべて成功**（実データ取り込み・学習を追加した版） |
| `npm run typecheck` | 成功（エラー0） |
| `npm run build` | 成功（アイコン生成を含む） |
| PC表示（1366×900, Chromium） | ダッシュボードなど9画面に加え、学習後の分析履歴、学習モデルを選んだオッズ画面、取り込み後の設定画面、実データの出走表を確認。横方向のはみ出し0px、コンソールエラー0件。ブラウザでの学習時間は約1秒（サンプル540レース） |
| スマートフォン表示（390×844, Chromium） | 同じ画面で横方向のはみ出し0px、コンソールエラー0件。オッズの買い目がカード表示になり、出走表もカード表示になることを確認 |
| ホーム画面への追加（PWA） | GitHub Pages と同じ `/boat-analyzer/` 配下で配信し、Chromium のインストール可否判定でエラー0件。実機（Android Chrome）でホーム画面に追加できたことを利用者が確認 |

テスト中に見つけて修正した不具合：
1. 期待収益率がちょうど閾値（例：20%）の候補が、浮動小数点誤差（0.19999999999999996）で除外されていた → 比較に許容誤差を追加
2. 過去に1着0回のコースの確率が厳密に0になっていた → 全場平均にラプラス平滑化を追加
3. サンプルデータで「風向：無風／風速4m」のような矛盾した値が出ていた → 生成スクリプトを修正
4. 期待収益率が+600%などの極端な候補がそのまま上位に出ていた → 「⚠要検証」の警告を追加
5. PC表示で、出走表が表とスマートフォン用カードの両方で表示されていた（CSSの指定順の問題、MVP当初から） → 表示切り替えの指定を最後に移して修正
6. 実データで過去レース（競走成績）にそのレース自身の結果が含まれ、予測に使われてしまう構造だった → 対象日より前のデータだけを使う索引に変更

- **スクリーンリーダーでの読み上げ確認**：未実施（ARIA属性とラベルの付与のみ）。
- **E2Eテストの自動化**：Playwright での確認は一回限りのスクリプトで、リポジトリには含めていません（依存を最小にするため）。
- **実物の公式ファイルでのテスト**：未実施。開発環境から公式サイトに接続できないため、公開されている解析例と同じレイアウトのテスト用ファイル（架空の選手）で確認しています。
- **実データでの学習・検証**：未実施（実データがないため）。
- **性能測定**：未実施（サンプル規模では操作に遅延がないことを目視で確認しただけです）。
