## 基本方針
1. 公式、または利用許諾を確認できる提供元を優先する。
2. 規約で認められていない自動取得（スクレイピング）や、アクセス制限の回避はしない。
3. 有料契約、外部へのデータ送信、デプロイは利用者の承認を得てから行う。
4. 取得したデータは `validateDataset()` で検証してから使う。

## 実装状況（2026-10-22）
**実装方式：利用者が手動でダウンロード・解凍した公式ファイルを、アプリに取り込む**

- アプリは公式サイトへ一切アクセスしません（自動ダウンロード・スクレイピングはしません）。
- 設定画面の「実データの取り込み」で、解凍済みのテキスト（番組表 B／競走成績 K）を選びます。データはブラウザの IndexedDB にだけ保存し、外部へは送りません。
- 解析処理：`src/data/official/`（Shift_JIS の読み込み、B・K ファイルの解析、アプリ形式への変換）
- ファイル形式の参考：MITライセンスの解析ライブラリ boatrace-lzh（PyPI）に含まれる解析処理とテスト用の例。テスト用のファイル（`tests/officialFixtures.ts`）は同じレイアウトで作りましたが、選手名・登番は架空です。
- **実物の公式ファイルではまだ試していません。** この開発環境からは公式サイトに接続できず、本物のファイルを入手できなかったためです。初めて取り込んだときに読めない行があれば、画面に理由が表示されます。

### 公式データに含まれないもの（アプリでの扱い）
| 項目 | 扱い |
|---|---|
| オッズ | なし。期待値は計算せず「オッズがありません」と表示 |
| 直線・回り足・周回展示・展示ST・チルト・部品交換 | 「データなし」と表示 |
| 展示タイム・進入コース | 競走成績から取得（確定後のレースのみ） |

## 連携の手順（予定）
1. 上の未確認事項を確認し、結果をこのファイルに記録する。
2. 公式ダウンロードの成績ファイルを手動で取得する（自動ダウンロードは規約を確認してから）。
3. 変換スクリプト（例 `scripts/import-official.mjs`）で `HistoricalRace` / `Race` の形式に変換する。
   - 欠損している項目は `null` にする（0で埋めない）。
   - メタ情報は `source: 'actual'`、`isDemo: false` とし、`updatedAt` に取得時刻を入れる。
4. `src/data/actualDataSource.ts` で変換済みのJSONを読み込み、`validateDataset()` を通して返す。
5. 認証が必要なAPIを使う場合は、APIキーをブラウザに出さないようにサーバ側（プロキシ）で保持する。`.env.example` には例示値だけを書く。
